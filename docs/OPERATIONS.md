# 中山社接龍維運手冊

這份文件提供秘書或後續維護人員日常使用。一般社員只需使用網站，不需要接觸 GitHub、Apps Script 或 Google Sheet 設定。

## 日常管理對照

| 需求 | 操作位置 | 是否重新部署 |
|---|---|---|
| 新增、停用或更名社員 | Google Sheet「工作表1」 | 不需要 |
| 更換社內通行碼 | Apps Script「指令碼屬性」 | 不需要 |
| 查看誰代填或取消 | Google Sheet「操作紀錄」 | 不需要 |
| 修改網站文字、畫面或互動 | GitHub 專案 | GitHub Pages 自動發布 |
| 修改 Sheet 欄位、驗證或後端流程 | `apps-script/Code.gs` | 需要重新部署 Apps Script |

## 更新社員名單

「工作表1」使用以下欄位：

- A 欄：永久社員 ID，例如 `m001`。
- C 欄：網站顯示的英文名字。
- E 欄：狀態；填入「否」、「離籍」、「停用」或 `inactive` 時不顯示。

新增社員時，請在新列填入一個從未使用過的永久 ID。既有社員即使更名或排序，也不可更改 A 欄 ID，否則過去報名與操作紀錄會失去對應。

Sheet 儲存後，網站會在重新開啟、重新取得焦點或最長約 15 秒內載入新名單。

## 更換社內通行碼

1. 開啟 Google Sheet 對應的 Apps Script 專案。
2. 點左側「專案設定」。
3. 在「指令碼屬性」修改 `ACCESS_CODE`。
4. 儲存即可，不需要重新部署。

更換後，已儲存舊通行碼的手機會在下次讀取資料時被要求輸入新碼。通行碼只應分享在既有 LINE 群組內。

## 查看代填與誤操作

- 「報名紀錄」顯示每位社員目前最後狀態，以及最後操作者。
- 「操作紀錄」保留每次建立、修改、取消與代填歷程。
- 社員在網站上快速切換「參加／不克」時，畫面會立即更新，後端依點擊順序寫入，最後一次點選為準。

目前所有已通過社內通行碼的社員都可建立活動、編輯活動及代填；尚未啟用獨立管理員權限。

## 發布網站前端

只修改 `index.html`、`assets/css/`、`assets/js/` 或圖片時：

1. 若變更 CSS 或 JavaScript，更新 `index.html` 對應檔案的 `?v=` 版本，避免 LINE 快取舊版。
2. 執行 `npm run verify`。
3. 提交並推送到 GitHub 的 `main` 分支。
4. 等待 GitHub Pages 顯示建置完成。

## 更新 Apps Script 後端

修改 `apps-script/Code.gs` 或 `appsscript.json` 時：

1. 將檔案內容同步到 Apps Script 編輯器並儲存。
2. 點「部署」→「管理部署作業」。
3. 編輯現有網頁應用程式，版本選「新版本」。
4. 按「部署」。

編輯既有部署時 `/exec` 網址不會改變；不要另建一個不必要的新部署。

## 故障判斷

- 一直要求通行碼：確認 Apps Script 的 `ACCESS_CODE`，以及手機輸入是否一致。
- 名單沒更新：檢查 A 欄 ID、C 欄名稱及 E 欄狀態，再重新開啟網站。
- 所有人都無法載入：檢查 Apps Script 部署是否仍允許「任何人」存取。
- LINE 顯示舊畫面：關閉 LINE 內建頁面後重開；維護者同時確認資源 `?v=` 已更新。
- 手機間資料不同：等待背景同步或重新開啟；目前資料來源皆為同一份 Google Sheet。
